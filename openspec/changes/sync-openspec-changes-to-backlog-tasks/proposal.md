## Why

OpenSpec changes are the canonical source for planning and design, but the team uses Backlog for daily Kanban-style execution tracking. We already sync `docs/` ↔ `.backlog/docs/` and `docs/adrs/` ↔ `.backlog/decisions/` via pre-commit hooks. We need a similar integration for OpenSpec changes and Backlog tasks so that an OpenSpec change can be projected onto the Backlog board without duplicating rich artifact content.

## What Changes

- New sync script: `tsx scripts/sync-openspec-change-to-backlog.ts`
- New reverse sync script: `tsx scripts/sync-backlog-task-to-openspec.ts`
- New pre-commit hook: `scripts/.git/sync-openspec-changes-to-backlog.sh`
- Backlog task files generated under `.backlog/tasks/` (active) and `.backlog/archive/` (archived)
- Backlog task bodies are **self-contained snapshots** with embedded content from OpenSpec artifacts (no external `@see` links)
- Only controlled fields sync back from Backlog to OpenSpec: status, checklist progress, notes, final summary
- Documentation: `docs/OPENSPEC-BACKLOG.md`
- AGENTS.md update with integration reference

## Capabilities

### New Capabilities

- `openspec-backlog-task-sync`: Generates a Backlog task from an OpenSpec change. The Backlog task contains self-contained embedded snapshots of OpenSpec proposal, design, specs summary, tasks, and plan. Frontmatter includes board metadata (status, labels, references to OpenSpec paths). Sync is one-way from OpenSpec to Backlog for content; Backlog can push back controlled fields.

- `openspec-backlog-archive-sync`: When an OpenSpec change is archived, generates or updates an archived Backlog task under `.backlog/archive/`. Removes the active Backlog task if it was generated by the sync (not manually created).

- `openspec-backlog-field-back-sync`: Reads Backlog task for status changes, checklist progress updates, and notes/final summary. Updates the corresponding OpenSpec change metadata (`.openspec.yaml` progress, notes) only for controlled fields.

### Modified Capabilities

- (none)

## Impact

- New files: `scripts/sync-openspec-change-to-backlog.ts`, `scripts/sync-backlog-task-to-openspec.ts`, `scripts/.git/sync-openspec-changes-to-backlog.sh`, `docs/OPENSPEC-BACKLOG.md`
- Modified files: `AGENTS.md` (add integration note), `.git/hooks/pre-commit` (add new hook), possibly `.backlog/config.yml` if new fields needed
- No changes to existing OpenSpec change structure or Backlog task schema — integration is additive
- Does not conflict with existing `docs/` ↔ `.backlog/docs/` sync hooks
