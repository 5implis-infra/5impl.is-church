# OpenSpec ↔ Backlog Task Sync Integration

## Overview

OpenSpec changes are the canonical source for planning and design in this monorepo. Backlog is used for daily Kanban-style execution tracking. This integration projects OpenSpec changes as self-contained Backlog tasks, keeping both systems in sync.

**Key principle**: OpenSpec is canonical for content; Backlog is an operational projection.

### Sync Direction

```
OpenSpec (canonical)  ──────→  Backlog (projection)
                              ←──────  controlled fields only
```

## How It Works

### OpenSpec → Backlog (Forward Sync)

When the pre-commit hook runs:

1. **Detect changes**: Scans `openspec/changes/` for active changes
2. **Generate task ID**: Increments from existing `.backlog/tasks/` files
3. **Build frontmatter**: `id`, `title`, `status`, `labels`, `references`, `documentation`
4. **Embed snapshots**: Content from `proposal.md`, `design.md`, `tasks.md`, `plan.md`, `verify.md` embedded with markers
5. **Derive status**: Based on `tasks.md` checklist completion (0%→To Do, partial→In Progress, 100%→Done)
6. **Validate**: Checks YAML frontmatter and body markers

Generated tasks are marked with `generated-by: openspec-backlog-task-sync` in frontmatter.

### Backlog → OpenSpec (Reverse Sync)

The reverse sync reads Backlog tasks and updates OpenSpec for **controlled fields only**:

- **Status changes**: Updates `.openspec.yaml`
- **Checklist progress**: Updates `tasks.md` checkbox items
- **Implementation Notes**: Appends to `notes.md` or `verify.md`

**Important**: Snapshot section content is NEVER written back to OpenSpec artifacts. This is a one-way guard.

### Archive Flow

When OpenSpec marks a change as archived (`status: archived` in `.openspec.yaml`):

1. Generates `.backlog/archive/<task-id> - <title>.md` with full snapshots
2. Removes the active `.backlog/tasks/<task-id> - <title>.md` if it was generated by sync (has marker and no manual content)
3. Preserves manually-created Backlog tasks on archive

## Snapshot Format

Each embedded section uses markers:

```markdown
## OpenSpec Proposal
*This section is generated from OpenSpec. Edit the OpenSpec artifact, not this snapshot.*
<!-- OPENSPEC:PROPOSAL:BEGIN -->
[content here]
<!-- OPENSPEC:PROPOSAL:END -->
```

Sections embedded:
- `PROPOSAL` - from `proposal.md`
- `DESIGN` - from `design.md`
- `TASKS` - from `tasks.md`
- `PLAN` - from `plan.md`
- `VERIFY` - from `verify.md` (if present)
- `SPECS-SUMMARY` - aggregated from `specs/**/spec.md`

## Troubleshooting

### Task not syncing
- Check that `proposal.md` exists in the OpenSpec change directory
- Verify the change directory is under `openspec/changes/`

### Status not updating
- Forward sync derives status from `tasks.md` checklist items
- If checklist is empty, status defaults to `To Do`

### Reverse sync not working
- Verify Backlog task has `generated-by: openspec-backlog-task-sync` marker
- Only controlled fields (status, checklist, notes) sync back

### CLI validation warning
- The sync scripts validate files directly even if Backlog CLI is unavailable
- This is expected behavior — validation still runs
